## Item 12: LiteLLM benchmark in detail

**Setup.**
- **Router arm:** the LiteLLM `complexity_router` with a **heuristic** classifier and four tiers on a single provider family. SIMPLE goes to Haiku 4.5, MEDIUM to Sonnet 5, and COMPLEX/REASONING to Opus 5.
- **Baseline arm:** every request goes to one frontier model with caching on. The companion doc says this is Opus 5 priced with a warm cache on continuing turns, and that the cache write after a switch counts against the router's saving.

**Datasets and results.** The blog says five datasets, but its table has four rows (the fifth is presumably the gateway switch-back set):
1. WildChat-1M simulation: 30,769 multi-turn conversations, **68.7%** cheaper.
2. DevGPT simulation: 1,011 conversations, **46%** cheaper.
3. Real agent traces with provider cache accounting: 95 sessions, 8,174 calls, **37.4%** cheaper.
4. TwinRouterBench static track: 81 multi-step instances, **44–50%** cheaper.
5. Live LiteLLM gateway traffic: 4,684 "switch-backs".

**How cache cost was computed.**
- On the gateway logs and agent traces, from provider `usage.cache_read_input_tokens` and `cache_creation_input_tokens`.
- **Modeled, not measured,** on the other three legs (the WildChat and DevGPT simulations and TwinRouterBench).
- Every turn gets one of three labels from a SQL window function partitioned by (session, model): "stay", "first visit to tier", or "return to tier".

**Key claim.** Switching models does not evict the earlier model's cache, so a later switch back can still hit it. Of the 4,684 returns to a previously used model, **97.4% were still warm at a 5-minute TTL and 99.3% at 1 hour**.

**Cache warmer.** A background warmer would prevent only 4% of misses. Net effect: +0.10% cost on chat (~1.7k-token prefix), +0.63% on agent traces with multi-hour gaps, and −0.9% on their agentic gateway (~190k-token prefix).

**Other claims.**
- A router with caching **off** costs about 4x a single cached model.
- Session affinity is now **off by default** (since v1.97, per the 2026-08-04 blog). Pinning is recommended only for cross-provider history problems (thinking blocks, `cache_control`, tool formats) or when style consistency matters. For multi-deployment tiers, they recommend also setting `deployment_affinity`.

**Caveats** (my assessment):
- **Quality is not measured** in the caching study. Only cost is reported, and quality comes from a separate study (97.1% / 87.3% retained vs Opus 5).
- Three of the five legs model cache behavior instead of measuring it.
- The real-trace leg is small (95 sessions).
- It is vendor marketing, and the classifier is heuristic.
- The 97–99% warm figure means the router alternates quickly between tiers. Each tier keeps its own warm prefix, but the **first visit to a tier still pays a full write**. Per-tier breakdowns of write cost are not published.
- The setup is a single-family ladder. Haiku 4.5 reads at 0.1x, but Opus 5.5 / Sonnet 5.5 now read at 0.05x, which raises the relative cost of misses. The results were computed on older-generation prices.
- TTLs were checked only at 5m and 1h. The OpenAI 30m/12h write premium (2.5x) is not covered.
- The study does not say whether prefix bytes were identical across tiers (system prompt and tool list per tier).

## Notable extra findings

- **The field has converged on cache-aware routing**, and none of these systems switches per turn without a guard:
  - Copilot Auto: switches only on the first turn or after compaction.
  - Copilot Fusion: keeps the main model fixed and gives helper models narrow context.
  - Not Diamond Code: explicit KV-cache state in a long-horizon objective.
  - Switchyard: hold turns, affinity, and docs that warn about switching.
  - Claude Code: TTL-aware switch confirmation and `PreModelSwitch` cost estimates.

  LiteLLM is the counter-example: affinity off by default, and it argues per-tier caches stay warm.
- **GitHub HyDRA blog** includes a comparison chart. It claims HyDRA (Conservative) ties OpenRouter Auto on resolution rate (70.8%) at 3.3x the savings, and that HyDRA (Aggressive) beats both Azure Foundry modes. This is vendor-reported.
- **Copilot docs on cache invalidation:** changing reasoning effort, context size, or the enabled tools/MCP servers mid-session invalidates the cache. Copilot gives cache TTLs as "24 hours for OpenAI models and 1 hour for most others" (that is Copilot's own setup). They recommend running subagents on cheaper models because subagents have their own sessions.
- **Claude Code effort changes:** on Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable 5.1 via the Anthropic API or a subscription, changing effort keeps the cache. This does *not* hold on Bedrock, Vertex, or gateways (secondary source summarizing the docs: https://wmedia.es/en/tips/claude-code-prompt-caching-slow-expensive-turns). This matters for open question 6 (routing effort as its own dimension).
- **Bedrock caching for GPT models:** GPT-5.6 and 6.x on Bedrock support explicit caching through InvokeModel, Chat Completions, and Responses (`prompt_cache_breakpoint`) with a 30-minute TTL, but **not through Converse**. A Converse-only router cannot cache these models.
- **LiteLLM PR #39210:** Bedrock returns 403 when it receives `cachePoint` for a model that doesn't support caching (the example is Nemotron). A mixed-tier router has to strip cache markers per target. https://github.com/BerriAI/litellm/pull/39210
- **OpenAI app-side caching:** for logged-in Codex and ChatGPT Work users, cached context is kept "forever" (Tibo Sottiaux, per secondary reporting). Product-side retention can therefore differ from API TTLs.
- **The NVIDIA blueprint is now officially deprecated.** The README points to Switchyard, which confirms the report's "deprecated → NeMo Switchyard" note.
