# LLM Routing Research Survey: Agent-Facing, Prompt-Cache-Aware Routing

Compiled 2026-11-04. Sources: the arXiv API and abstract/HTML pages, plus GitHub and vendor docs. Every paper below has a URL that I actually opened or that the arXiv API returned.

**Verification levels used in this document**
- "Verified" means I read the claim on the abstract or HTML page.
- "(abstract-level)" means I read only the abstract, not the body.
- "unverified" means I recalled it or could not confirm it on a page I fetched.
- Repo links were checked by HTTP status (200) on github.com. "Repo exists" does not mean the repo is linked from the paper unless I say so.

**Column legend**
- **Gran.** = decision granularity: query / turn / session / subtask / step.
- **Signals** = what the router decides on.
- **Cache** = cache awareness. "none" means the router ignores it. "sticky" means it uses an affinity or hold rule. "cost-modeled" means cache cost is explicitly part of the objective.

**Takeaway.** Every classic router decides per query and treats a request as independent. None models prefix-cache state or switching cost. Two separate results (the kNN paper 2505.12601 and Routing Plateau 2606.07587) show that simple embedding baselines are about as good as anything else on query-only signals. That suggests the marginal value lies in *new signals* (trajectory, session state, cache state), not in fancier query classifiers.

**Takeaways**
- 2026 has many **step-level** routers: AgentRouter, BoPO, R2V, Hera, Sibyl, ProgRouter, GraphPlanner, and OpenSquilla.
- None of them, at the abstract level, charges a cache-invalidation cost for switching. Most report cost as tokens × list price, which overstates the savings from switching when the incumbent model has a warm cache (TurnCost: about 7x overstatement under flat pricing).
- Approaches that switch once and never return are implicitly cache-friendly. These are SWE-Router (explore, then decide) and TACIT-Switch (permanent handoff).
- Session- or turn-aware routers (Arch-Router, SeqRoute, "Whose turn") show that **session history improves routing quality**.

MapFlow reuses attention maps across models. | Reduces the switch penalty | **Only applicable to self-hosted open-weight models.** Provider APIs (Anthropic, OpenAI, Bedrock) do not expose KV state, so for our router a provider-model switch always pays full uncached input. |

**Empirical cache facts for agent traffic**
- **GitHub Copilot production traces** (https://arxiv.org/abs/2608.00101; 761M LLM calls): KV hit rate is about 90% *within* a turn and about 55% *across* turn boundaries. Cache is "drastically invalidated by model switches or context compaction". User idle gaps at turn boundaries last minutes, which interacts with cache TTL.
- **Microsoft M365 agentic traces** (https://arxiv.org/abs/2610.22863; 121M calls): about 80% of context tokens come from the prefix cache in Deep Research. When the next call lands on a different deployment, cached-context reuse drops from 89% to 29%.
- **TurnCost:** 98.6% of input tokens are cache hits in SWE agent loops.
- **Enterprise coding case study** (2607.13080): 99.3% hit rate and an 88.6% cost cut.

**Industry and gateway features (cache-sticky, not cost-modeled)**
- **OpenRouter**, provider sticky routing (https://openrouter.ai/docs/features/prompt-caching):
  - Routes subsequent requests for the *same model* to the same provider endpoint.
  - Activates only when cache-read price is below regular input price.
  - Expires after 10 minutes idle.
  - Disabled when a manual provider order is set.
  - It is not cross-model.
- **LiteLLM** `session_affinity` / `deployment_affinity` (https://docs.litellm.ai/docs/routing):
  - Pins a conversation to the deployment that served its first request, explicitly for provider-side prompt caching.
  - `deployment_affinity_ttl_seconds` defaults to 3600.
  - Works within a model group.
  - A "Cache-Aware Routing" docs page exists, but I could not read it (unverified).
- **Arch-Router / archgw (plano):** per-turn policy routing, no cache logic found.

**Adjacent: KV-cache-aware scheduling across replicas of the same model.** These systems are different from our problem: they choose a *replica*, while the client chooses the *model*.
- **Preble** (https://arxiv.org/abs/2407.00023, https://github.com/WukLab/preble): distributed prompt scheduling that co-optimizes KV reuse and load (E2 scheduling). Venue ICLR 2025 is unverified.
- **SGLang Model Gateway / sgl-router** (https://github.com/sgl-project/sglang/tree/main/sgl-model-gateway): `cache_aware` policy keeps an approximate prefix tree per worker and balances against load thresholds. Its multi-model "IGW" mode applies *per-model* policies, but the model is chosen by `model_id`, not by the router.
- **NVIDIA Dynamo** (https://github.com/ai-dynamo/dynamo): KV-aware router scoring workers on load plus KV overlap.
- **llm-d** (https://github.com/llm-d/llm-d): prefix-cache- and load-aware balancing, with session-aware routing for agents.
- **Mooncake** (https://arxiv.org/abs/2407.00079, https://github.com/kvcache-ai/Mooncake): KVCache-centric prefill/decode disaggregation with a global KV pool. FAST'25 is unverified.
- **Lodestar** (https://arxiv.org/abs/2606.00946): online-learned replica router.
- **vLLM production-stack** (https://github.com/vllm-project/production-stack) and **vLLM Semantic Router** (https://github.com/vllm-project/semantic-router): the latter routes by category/semantics to models, and I found no evidence of cross-model switch-cost modeling (unverified).
- Lesson to borrow: score candidates by `expected_cache_overlap × prefix_len` minus a load penalty. In our case, "overlap" is the *provider-side* cache state of (provider, model, account/region, prefix-hash, TTL).

## (a) Gaps: what no paper I found addresses for agent + cache routing

1. **Cache-aware *learned* quality routing for agents.**
   - The cache-modeled works ("Whose turn", Harness Tokenomics, TurnCost) use zero-shot LLM routers, closed classifiers, or pure analysis.
   - The learned step-level routers (AgentRouter, BoPO, R2V, Hera, ProgRouter) ignore cache.
   - No one trains a policy whose reward uses **cached-token-aware realized cost**, with switch cost in the MDP state.
2. **Provider-API reality.**
   - Cross-model KV transfer (KV-Lingo, CacheBridge, MapFlow) does not apply to closed APIs.
   - No paper models per-provider cache semantics jointly: write premiums (1.25x for 5 min / 2x for 1 h), minimum prefix lengths, explicit vs implicit breakpoints, TTL refresh-on-read, cache scope (org/workspace/key, cf. KeyPooling https://arxiv.org/abs/2608.17485 and CacheProbe https://arxiv.org/abs/2605.30613), and regional/cross-region inference effects.
   - Harness Tokenomics comes closest, with a price-sheet table and TTL simulation.
3. **Uncertainty over the remaining horizon.** Every break-even rule needs "remaining calls on this model" (k\*, n\*, T − j). No router *predicts* the remaining turns or tool steps in a session and plugs that prediction in. The Copilot idle-time predictor (2608.00101) is the nearest building block.
4. **Sub-agent and side-channel topology as the routing lever.** Harness Tokenomics and CacheRouter argue for routing at fresh-context boundaries (subagent spawn, side lanes, tool-router channels) instead of swapping the main model. No benchmark measures quality, cost, and cache together under that design.
5. **Compaction and summarization events** reset the cache anyway (Copilot traces). They are free switch points, yet no router exploits them explicitly.
6. **Benchmarks.**
   - TwinRouterBench, RouterWorld, and SWE-Router's dataset are step- or trajectory-aware.
   - None scores routers on *cache-realized* cost with TTL, write premiums, and switch penalties.
   - RouterArena and RouterBench are per-query only.
7. **Asymmetry-aware policies.** The finding that downward switches pay back quickly and upward ones rarely do (2610.19292) has not been turned into a learned hysteresis or one-way-escalation policy evaluated end-to-end. TACIT-Switch is one-way but cache-blind.
8. **Multi-provider fallback and failover** (rate limits, outages) that preserves cache: re-pinning policies exist only in gateways (LiteLLM `session_affinity_repin_on_failover`), with no research evaluation.

## (b) Most relevant papers for our design

1. **Whose turn is it? Context-guided model routing for stateful agents.** https://arxiv.org/abs/2610.19292. Turn-boundary routing with session history, plus a closed-form, context-length-independent switch break-even and the up/down asymmetry. Directly usable as our switch-cost model.
2. **Harness Tokenomics: A Router for the Enterprise Agentic Control Plane.** https://arxiv.org/abs/2609.28919. The closest system design to ours:
   - Routes at session start, subagent launch, and side lanes.
   - Uses a hold-unless-confident threshold and a payback rule with cache write/read prices and TTL.
   - Finds the premium-model crossover on long sessions.
3. **TurnCost: Cache-Aware Loop Engineering for Coding Agents.** https://arxiv.org/abs/2610.15093. Shows that cached-token pricing changes the economics (about 7x), that delegation often *increases* cost, and that turn count dominates. It provides a re-scoring tool for offline evaluation of our policies.
4. **TwinRouterBench** (https://arxiv.org/abs/2605.18859, code https://github.com/CommonstackAI/TwinRouterBench) and **SWE-Router** (https://arxiv.org/abs/2607.00053). These are the best available step- and trajectory-level agentic routing benchmark and method. We would add cached-token cost accounting on top.
5. **CarbonRouter / Context Is Not Free** (https://arxiv.org/abs/2610.35230). A cache-aware cost model plus a "don't move if you'll move back" gate, a clean template for anti-ping-pong stickiness. Pair it with **Arch-Router** (https://arxiv.org/abs/2506.16655) as an open, history-aware per-turn policy classifier we could reuse for the quality side.
