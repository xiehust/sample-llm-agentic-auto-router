## 0. Landscape changes in 2025–2026 (read first, or the names below will confuse you)

- **SGLang** has two routers in the repo. The new slim `sgl-router/` is driven by KV events. The old gateway `sgl-model-gateway/` is a mirror of SMG (Shepherd Model Gateway, now at `smg-project/smg`) and is being deprecated. The new router removed `--cache-threshold / --balance-abs-threshold / --balance-rel-threshold`, and there is no one-to-one replacement.
- **GIE (Gateway API Inference Extension)** keeps only the InferencePool API (v1 GA), a lightweight round-robin EPP, and the conformance tests. The EPP itself, InferenceObjective (formerly InferenceModel) and BBR moved to `llm-d/llm-d-router`.
- **llm-d**: `llm-d-inference-scheduler` redirects to `llm-d-router`. `llm-d-kv-cache-manager` was renamed `llm-d-kv-cache`, and its routing code also moved into llm-d-router. So "GIE EPP plugins" and "llm-d scheduler plugins" are now **the same codebase**.
- **Dynamo** (v1.6 era): the cost function was refactored into a policy YAML. `kv_overlap_score_weight` became `prefill_load_scale` (the old flag is removed in v1.7). It adds session affinity (including sub-agent parent-session grouping), a ThunderAgent program-level router, and a multi-DC Pool Relay that syncs Cuckoo-filter summaries.

Cross-system patterns:
1. **Two families: precise vs approximate.** Precise relies on engine KV events. Approximate means the router remembers where it sent each prefix, plus TTL/LRU. The llm-d benchmark gap (P90 0.54 s vs 31 s) shows how far an approximate index can drift under heavy KV pressure.
2. **Hashing consensus**: chained block hash `h_i = H(block_i, h_{i-1})`, seeded with model/LoRA/salt. Blocks are about 16–64 tokens, or 64–128 B when not tokenizing. Hash the **rendered** prompt (template plus tools) where possible; production-stack ignores template and tools and gets it wrong.
3. **Trade-off forms**: (i) gate then affinity (SGLang 32/1.1/0.5, Ray, AIBrix σ gate); (ii) normalised linear `hit − β·load` (production-stack); (iii) additive cost with load measured in **uncached tokens** (Dynamo, sgl-router, llm-d, Mooncake, Preble), which puts cache benefit and load in the same unit and is the most principled; (iv) sticky-set filter + penalty breaker (llm-d 18 s); (v) exploit only if `cached > missed` (Preble).
4. **Every system has an escape hatch for an overloaded holder**: credit decay, hysteresis (factor 2 AND gap), penalty breaker, replicating the hot prefix, P2P KV fetch, queue / early reject.
5. **Multiple router replicas: no system offers strong consistency.** The options are event fan-out to every replica, Redis/gossip eventual consistency, a central actor, or a single global scheduler. **Consistent/rendezvous hashing is the only way for replicas to agree with zero sync.**
6. **Fan-out race**: siblings that arrive before the cache state updates get scattered. Everyone records the decision at route time with a short TTL (sgl pending prefix, llm-d speculative 2 s, Dynamo predicted 5 s).

## 2. Mechanisms that carry over to a router that sees only request content, not backend KV (e.g. commercial APIs)

Shared premise: in this model an "endpoint" = (provider, account/org/workspace, region/deployment, model[, cache-related params]). Data: M365 traces show that when the next call lands on a different deployment, reuse drops from 89% to 29%; Copilot shows that after a model switch the hit rate is only about 8%. So the affinity key **must include all of these dimensions**. The provider's internal replica routing is invisible to us; we can only treat the whole endpoint as one cache domain.

### M1. Rendered-prefix fingerprint (chained block hash)
- **What**: render the request as `tools → system → messages` (canonical JSON, fixed key order), cut it into blocks of fixed bytes or estimated tokens, and compute `h_i = H(block_i, h_{i-1})`. Seed `h_0` with `(provider, account, region, model, cache scope)`. Keep several depth levels (system+tools; up to each cache breakpoint; full prefix). Sources: GIE 64 B no-tokenization design, AIBrix tools-first + 128 B blocks, SMG multi-depth `--cache-boundaries`.
- **Premise**: the provider's cache is an exact prefix match (true for all mainstream APIs). The router can render deterministically.
- **Limits**: provider-side tokenization and templating are unknown, so a block boundary does not equal a cache boundary. Explicit-breakpoint providers (e.g. Anthropic) can only hit at breakpoints or within the lookback window, so **hash at breakpoint boundaries**, not uniform blocks. Automatic-cache providers need a minimum length and match at a granularity (exact rules are with session A). Images, documents and thinking blocks need their own canonicalisation.

### M2. Predict-on-route approximate cache index + TTL warmth model
- **What**: following Dynamo approximate mode (TTL 120 s), AIBrix (20 min), Ray/GIE (LRU), write `(endpoint, prefix-hash) → last_touch_ts, est_cached_tokens` every time a request is routed. For a commercial API, set TTL = the provider's documented TTL. Remember that Anthropic counts TTL from **request start** and refreshes it on each hit. Don't output a binary warm/cold; output **P(warm | Δt)**. Calibration points from agent traces: Δt<2 min ≈ warm (Copilot ≥95%), 2–10 min uncertain (≈70% with a heavy tail), >10 min ≈ cold under a 5-min TTL. 1-hour TTL: TraceLab ideal hit at 1 h is 98.6%.
- **Premise**: the provider honours the documented TTL and does not evict early.
- **Limits**: the provider may evict early under pressure (no SLA). Its internal multi-replica routing may make the cache non-shared (some providers need a `prompt_cache_key`-style hint to raise hit rate, which session A covers). Early eviction can't be predicted, hence M3.

### M3. Use response usage as the "KV event" (closed-loop calibration) ★ the most important carry-over
- **What**: usage fields in the response (e.g. cached read/write token counts) are a **delayed but precise** per-request cache event. Write them back into the M2 index: a miss despite a "warm" prediction marks that `(endpoint, prefix)` cold and lowers that endpoint's effective P(warm). A write refreshes `last_touch`. Over time you learn each endpoint's effective TTL and hit rate. This is the commercial equivalent of llm-d/Dynamo moving from approximate to precise.
- **Premise**: the provider returns cache-hit fields (all mainstream providers do; field names are with session A).
- **Limits**: you only learn after the fact, and only for the request you actually sent (no lookup for other prefixes). Streaming responses deliver usage only at the end. You can't tell which block missed, only the total hit/miss token count.

### M4. Hierarchical affinity keys + session / parent-session grouping
- **What**: key priority is explicit header (`x-session-id` / client-supplied) > parent-session (sub-agent grouped to its parent, following Dynamo `X-Dynamo-Parent-Session-ID` / `x-claude-code-parent-agent-id`) > prefix fingerprint (system+tools hash = "agent template family") > tenant. Two levels: **hard** (strict pin) vs **soft** (advisory, can be overridden by M6). Idle TTL is tied to the provider TTL (expiry = affinity worthless).
- **Premise**: clients pass a session/agent ID, or the router can infer one from the fingerprint.
- **Limits**: a sub-agent's prefix (its own system prompt) differs from the parent's; what it shares is usually only tools/system. Parent grouping mostly saves on the **template family** layer. When the provider's cache is shared org-wide (e.g. Anthropic isolates by org/workspace), template-family affinity only needs the same org + region + model, not the same "replica".

### M5. Consistent / rendezvous hashing for multiple router replicas with zero sync
- **What**: map affinity key → endpoint with rendezvous hashing or a consistent-hash ring (production-stack uhashring, AIBrix rendezvous, SMG 150 vnodes), using **bounded load** (SMG `prefix_hash`: overloaded if `inflight > factor·avg AND > avg+abs` → move to the next ring candidate). Router replicas agree without sharing state; an M2/M3 index (local or Redis/gossip, eventually consistent) only adds fine-tuning on top.
- **Premise**: the candidate endpoint set is fairly stable.
- **Limits**: when endpoints are added or removed, ~1/N of keys move (one cold start). Under bounded load, a spill also scatters cache. Weighted endpoints (different quotas/prices) need weighted rendezvous.

### M6. Cost-normalised trade-off: price load and cache in the same unit
- **What**: following Dynamo/sgl-router/Mooncake/Preble (load in uncached tokens / estimated TTFT), for each candidate endpoint e:
  `cost(e) = $price(e, uncached_tokens(e), cache_write(e), cache_read(e)) + λ·E[latency(e)] + μ·P(throttle(e))`,
  where `uncached_tokens(e) = prompt − P(warm|e)·est_cached(e)`. Gates: affinity only if expected cached tokens ≥ threshold (sgl-router 1024 tokens; Autellix ≤2K requests load-balance freely; Preble `cached > missed`). Hysteresis: leave the holder only if `cost(holder) > k·cost(alt)` **and** the gap exceeds an absolute amount (sgl-router k=2 + gap), to avoid flapping.
- **Premise**: you can estimate per-endpoint price, latency (EWMA/TTFT) and throttle probability (429 rate, rate-limit headers).
- **Limits**: a commercial API's "load" is mostly invisible; you can only use proxies like your own in-flight requests, rate-limit remaining headers, recent latency and 429/529 rates (lagging). λ and μ need tuning per business SLO.

### M7. Holder overload / unavailable: penalty breaker + circuit breaker
- **What**: following llm-d's TTFT penalty breaker (drop stickiness when it's 18 s worse) and Mooncake's early rejection: when the affinity endpoint's predicted penalty exceeds the saved re-prefill cost, or it is returning 429/529/5xx, break affinity, pick by M6, and record a session "migration". Within one session, migrate at most once per short window to avoid cache thrashing.
- **Premise**: you can measure throttling and latency in real time.
- **Limits**: migration costs a full re-prefill (median context 68–126K tokens, ~1M for deep loops). The penalty threshold should scale with **this session's estimated cached tokens** (see §3).

### M8. Fan-out: route-time stakes + "send one first, release the rest"
- **What**: when sibling requests with the same prefix arrive (parallel tool calls, sub-agent fan-out, n>1), write a short-TTL "pending" stake at route time (sgl pending prefix, llm-d speculative 2 s, Dynamo predicted 5 s) so siblings go to the same endpoint. For commercial APIs, per Anthropic's docs, **send one first, release the siblings once it starts streaming** (or pre-warm with `max_tokens: 0`); otherwise N concurrent requests each pay a cache write. Cap followers (sgl `max-followers`) to avoid a herd.
- **Premise**: the router can briefly hold sibling requests (or the client cooperates).
- **Limits**: adds about one TTFT of latency to the siblings. Real wide fan-out is rare in agents (Copilot: 93% of tool batches are single; production platform: only 0.2% of siblings actually overlap), so this matters mostly for research/swarm agents.

### M9. Affinity break points = free rebalancing (and model-switch) windows
- **What**: detect these events and, at those moments, re-place the session or switch models (layer 1) for free:
  ① idle > provider TTL (P(warm) ≈ 0);
  ② **compaction/context editing**: prompt length drops sharply, or the hash after the system/tools block no longer matches;
  ③ first call of a user turn (Copilot mean hit rate only ~45%);
  ④ a new sub-agent (small context).
- **Premise**: the router can see session history (at least the previous request's fingerprint, length and timestamp).
- **Limits**: model switches outside these windows cost a lot (hit rate falls to ~8% after a switch). So **layer-1 model selection should be session-sticky with hysteresis**, with downgrades done at break points or via sub-agents (as Claude Code does: Opus delegates to Haiku explore sub-agents).

### M10. Keep-alive / pre-warm for idle that straddles the TTL (optional)
- **What**: the Copilot paper suggests a keep-alive just before the TTL expires when predicted idle straddles 300 s (they predict idle with LightGBM, AUC 0.73). The Continuum idea (choose a pin TTL from the tool-latency CDF) maps to: **pick a 5 min vs 1 h TTL per session/breakpoint from predicted idle**.
- **Premise**: the provider supports a refresh-able TTL / selectable 1-hour TTL, and a keep-alive (cache read) costs less than a re-prefill.
- **Limits**: only worth it for large-context sessions. Wrong predictions waste money. The pricing calculation needs session A's data.

### M11. Cache-breaker linting / normalisation
- **What**: the router detects and exposes metrics for timestamps/UUIDs in the system prompt, non-deterministic tool/JSON key ordering, tools added or removed mid-session, and changes to tool_choice/thinking params. It can optionally **deterministically sort tools and normalise JSON keys** (AIBrix canonicalises tools; Manus and Anthropic both list these as top cache killers).
- **Premise**: the normalisation is semantically equivalent.
- **Limits**: rewriting a request may change model behaviour (tool order affects the model slightly), so make it opt-in. Dynamic content inside the system prompt can only be reported, not fixed.

### Not transferable (or only as a concept)
- Precise KV events, KV block indexes and gap replay: commercial APIs don't expose them (M3 is the only approximation).
- KV transfer/sharing (LMCache P2P, Mooncake Store, CacheBlend) and hot-prefix replication: you can't move KV between providers. The closest analogue is "deliberately warming another endpoint" (spending a cache write on a hot template family to scale out), which can be modelled as an M6 decision.
- Eviction policy control (KVFlow, Continuum pinning, Penelope, TokenCake): it lives on the backend. Only the TTL choice idea carries over (M10).
- The fine-grained load signals that inference-layer formulas depend on (queue length, KV usage, prefill tokens) only exist for **self-hosted endpoints**. If the router also manages self-hosted vLLM/SGLang, plug in llm-d/Dynamo/sgl-router directly as the layer-2 executor, and keep only M4/M5/M6 in our router.

Continuum (tool-call TTL pinning): JCT up to 8× (some benchmarks 1.12–3.66×, conflicting numbers). KVFlow: up to 2.19×. | 2407.00023, 2502.13965, 2511.02230, 2507.07400 |
| Public traces | Usable for simulating router policies: Qwen Bailian (16-token block hashes + parent_chat_id), Mooncake toolagent (512-token hashes; but its gaps median ~2 min, unlike real agent loops), TraceLab (agent-realistic gap/append distributions). Azure and BurstGPT have no prefix information. | C-notes-3 §4a |

**Implications for the design:**
1. Within a turn, gaps are about 1 s, far below any TTL, so **session-sticky routing alone can reach 90%+ hit rates**. It's the main lever, so do M4/M5 first.
2. A miss costs a re-prefill of about 60–120K tokens (deep loops ~1M), so **the M7 penalty threshold and the M6 affinity weight should scale with the session's estimated cached tokens**, not use a fixed value.
3. Rebalancing and model switching are almost free at user-turn boundaries with idle > TTL, after compaction, and when a new sub-agent starts (M9). Elsewhere, staying put is the default.
4. **System + tools template families** are an important source of hits across sessions (Mooncake toolagent: 34% of blocks are hits on 18 hot system blocks; Qwen to-B: 97% of hits come from shared system prompts). Even a new session gets a floor hit rate when sent to the org/region/model that already has its template warm.
